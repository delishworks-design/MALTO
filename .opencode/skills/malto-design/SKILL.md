# MALTO Design Skill

## Core rule
Improve the existing MALTO design system instead of replacing it.

Before styling a component, inspect the project's existing design-system and global styles and reuse their tokens, typography, spacing, colors, and component patterns.

## Design goals
MALTO should feel:
- intentional
- refined
- trustworthy
- calm
- premium
- easy to use

Avoid:
- generic AI-generated dashboard aesthetics
- excessive gradients
- excessive glassmorphism
- random rounded containers
- decorative noise
- unnecessary animations
- inconsistent typography

## Interaction quality
For important interactive elements, account for:
- default
- hover
- focus-visible
- active
- disabled
- loading
- success
- error

Use motion only when it communicates state or improves continuity.

## Responsive quality
Check 360px, 390px, 430px, tablet, 1280px, and 1440px widths. Fix overflow and awkward wrapping rather than hiding content.

## Accessibility
Use semantic HTML, visible focus states, useful labels, keyboard-accessible controls, appropriate button/link semantics, and sufficient contrast.

## Visual QA
For substantial UI work, inspect the result in a real browser. Do not declare visual work complete from source code alone.
